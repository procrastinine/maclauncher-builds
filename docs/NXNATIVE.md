# nxnative native tools

The `nxnative-tools` package contains the ARM64 native host, package extractor, shader translator and compiler tools, pinned Python dependencies, .NET runtime and launcher adapters. It requires Apple Silicon and macOS 26 or later. Compatible CPython is supplied by MacLauncher through a private environment; no interpreter or standard library is duplicated in the runtime package.

Upstream nxnative scripts, game profiles and source data are selected separately from https://github.com/seedds/nxnative. They are absent from the native-tools payload. MacLauncher downloads the selected upstream commit directly and records its full revision and commit date. Local custom source directories retain a content identity instead of a fabricated Git commit. Native tool versions record their own source revision and commit date independently.

Legacy self-contained installations retain their original `nxnative` identity and source snapshots. Existing installed files and historical catalog records remain valid; the active producer publishes only `nxnative-tools`.

## Source and execution

Preparation accepts NSP, XCI, NSZ or XCZ application containers. Encrypted content uses a separately selected local keys file. Original archives, keys and upstream source remain unchanged. Rewritten modules, shader data, generated fonts, logs and saves use per-application working directories.

MacLauncher supplies `NXNATIVE_PYTHON` for the resolved isolated interpreter and `NXNATIVE_SOURCE_ROOT`, `NXNATIVE_SOURCE_REVISION`, and optional `NXNATIVE_SOURCE_COMMITTED_AT` for the selected source. Managed source receipts identify an exact upstream commit; custom source receipts identify the selected directory and its content. Metadata-only program inspection needs no source snapshot. The launcher verifies managed source installations. The command adapter checks the selected source layout and uses its scripts; it does not repeat source inventory verification. Source is copied into a writable workspace keyed by tool version and source identity, without changing the selected source tree.

The native host accepts its compiled shader-chain format. Preparation computes the selected source chain with the managed tool fingerprints and rejects an incompatible format before extraction. The workspace includes the production inputs declared by the selected shader-chain tool, including vendored translator lowering sources. The adapter supplies the managed SPIRV-Cross path explicitly and accepts the upstream toolchain callback arguments. This checks actual interfaces and format identity rather than a list of allowed source commits. A source change requiring a different native format needs compatible native tools.

The package retains only the compiled shader-translator closure and generated toolchain metadata. Upstream source supplies the Python tools, profiles and tables. Nintendo button fonts are generated by the upstream font tool and system fonts. Metal calls without an optimization override retain explicit MSL source objects, compiled by the native loader through the system Metal API. Calls requesting `-O1` use the Apple Metal compiler with the original arguments, including `-fpreserve-invariance`, and produce native AIR and metallib files. Native AIR and source objects cannot be linked together. The package declares a managed Apple Metal toolchain and checks it before preparation. MacLauncher supplies its verified `Metal.xctoolchain` root through `MCL_APPLE_METAL_TOOLCHAIN_ROOT`. The adapter retains explicit compiler options and SDK selection; without a caller SDK it uses the declared target SDK version. Existing system compiler and source-object paths remain available. Apple compiler files are downloaded separately from Apple and are absent from the native-tools package.

## Producer

The exact native source is registered at `sources/nxnative`. Owned recipes and platform adapters are in `producers/nxnative`; `source.json`, `dependencies.json` and `nx-extract.lock.json` select the native inputs. The upstream checkout remains unchanged. Corresponding source stays in its source repository and is not selected into the runtime release.

The producer requires Node 24 or later, the .NET SDK and the macOS SDK declared in `source.json`. Authoring uses pinned Python binaries; the package recipe excludes the authoring interpreter and upstream source tree. Output archives use the normal immutable managed-runtime catalog format under project `nxnative-tools`.

`build.mjs` creates an authoring output, `refresh-runtime.mjs` reuses a verified compatible native output for adapter changes, and `package.mjs` selects the native runtime payload. Refresh requires unchanged native inputs and a new version; earlier sealed packages remain intact.
