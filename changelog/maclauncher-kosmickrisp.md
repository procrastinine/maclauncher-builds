# MacLauncher KosmicKrisp

## 27.0.0-devel-MCLv13

The default performance mode selects its capabilities for the running Apple GPU family. On Apple7 to Apple11 it reports mesh and task shaders, fragment shader barycentrics, multisampled rendering to single-sampled images, vertex input dynamic state, multiview with geometry and tessellation shaders, block-compatible views of several layers, descriptor heaps, non-seamless cube maps, shader module identifiers, graphics pipeline libraries, mixed Float16 dot products with Float32 accumulation and explicitly zero-initialized device memory. Graphics pipeline libraries provide all four library parts, independent pipeline layouts and independent interpolation decorations, and link eligible vertex and fragment stages into native pipelines. Apple7 and Apple8 render direct mesh draws through native Metal mesh pipelines and prepare indirect mesh inputs before each rendering scope. Apple7 reports 64-bit integer image atomics, which it performs on the two 32-bit words of each texel under a lock; Apple8 and later publish each result through a native 64-bit texture minimum or maximum. Lines drawn from mesh shaders support the rectangular and smooth line modes. Queued native compilations of compute pipelines that are destroyed before use are cancelled.

In conformance mode (`KK_EMULATION=conformance`), vkd3d-proton reports Direct3D feature level 12_2 and shader model 6.9. Variable rate shading through `VK_KHR_fragment_shading_rate`, with fragment sizes up to 2x2 pixels and per-primitive rates from mesh shaders, and the depth bounds test on Apple7 to Apple9 are reported in conformance mode or when `KK_EMULATION` selects them. Conformance mode also reports ray tracing: acceleration structures, ray queries and ray tracing pipelines, built and traversed in compute passes without Metal ray tracing.

Sparse residency also covers 2D storage images and block-texel views of compressed 2D images. On Apple7, sparse binding and sparse residency are reported with macOS 26 releases before 26.4 as well.

The Metal pipeline archive is kept across driver updates, so a pipeline whose generated Metal Shading Language and descriptor are unchanged loads from it instead of compiling again; a macOS or Metal update starts the archive over. Metal libraries are reused by source digest, recorded archive pieces open in the background, and on macOS 27 and later the archive is saved at intervals during long compile loads. The vertex and fragment libraries of a graphics pipeline compile in parallel. Creating a compute pipeline, or restoring one from a pipeline cache, leaves its translation to Metal Shading Language and its native build to a background build, which stores the translation in the shader cache for later runs; a compute pipeline that the game bound in an earlier run builds as soon as it is created, and other background builds wait until the compiles that pipeline creation or a bind waits for have finished. Destroying a compute pipeline does not wait for its build. Compute pipelines in a pipeline cache carry a checksum, so damaged entries are rejected and compile from SPIR-V; a compute shader that fails to translate returns the error at pipeline creation in later runs; and background builds do not call the game's debug messengers. Compute pipelines that a cache-only creation restores from the shader cache also build in the background instead of on the creating thread. Compute shaders use less memory after they are built. Pipeline creation feedback times creation in steps of about 42 ns, so pipelines created from a cache no longer report a duration of zero. Shaders that sample textures compile faster, and textures sampled while sampler emulation is active run faster on the GPU. Sampler LOD bias applies on Apple GPU families below 10 again, and LOD queries on array textures no longer crash pipeline creation. Descriptor heap samplers return their border color outside the texture instead of a blend of the edge texel and the border. A render pass that covers only part of its attachments waits for the earlier passes in its command buffer to finish their fragment work and attachment stores, so blits, resolves and atlas tiles drawn as separate passes keep what earlier passes stored, and each such pass gives up the fragment overlap with the pass before it. Thin lines in the default rasterization mode whose endpoint lies on a pixel row boundary draw their last row. Point-mode polygons clipped by the view volume no longer draw points at its corners. Mesh shader triangles in point polygon mode draw points at their vertices instead of filled triangles. Mesh shader pipelines that set the line rasterization mode at draw time draw smooth and rectangular lines correctly. Mesh shader lines with a static last-vertex provoking mode take flat values from their last vertex, and Mesh points without a point size write draw at size 1. Mesh shader pipelines with a dynamic provoking vertex mode take flat values from the vertex the draw's mode selects. Mesh shader pipelines whose fragment shader reads per-vertex inputs (pervertexEXT) are now created.

Timestamp query pools take their entries from timestamp heaps the device shares, so a process is no longer limited to about 32 live timestamp query pools, and a pool of more than 4096 queries no longer first creates heaps that Metal rejects. A request that fails releases the heaps it added, and a query pool creation that runs out of memory writes one warning naming the query count, the query type and what ran out. A render pass that writes timestamps for several query pools takes one sample per render stage, so its later timestamps no longer read 0. Timestamps written outside a render pass in a compute encoder stay available, nonzero and non-decreasing: each reports the encoder's first sample at no GPU cost, so a duration measured within one compute encoder is 0. The precise_timestamps behavior entry, on in conformance mode and off by default in performance mode, makes each such timestamp wait for the encoder's earlier dispatches and record its own time, at about 7 microseconds of GPU time per timestamp on Apple8. GPU encoder timing (KK_PERF_TRACKING_GPU_ENCODERS) uses at most two shared timestamp heaps instead of one heap and an encoder proxy per encoder, so it no longer faults with more than 32 timed encoders, and it reports render encoders without draws and compute encoders holding only copies and fills as zero-work spans. Mesh shader triangles in point polygon mode give their points the triangle's facing, so a fragment shader that reads gl_FrontFacing sees it. Shaders that use descriptor heaps, descriptor buffers or buffer device addresses compile their sparse residency guards only after the application creates its first resource with sparse residency, as descriptor-set shaders already did, so translators such as vkd3d-proton no longer compile the guards into almost every shader. A copy, clear or dispatch that follows a render pass covering only part of its attachments waits for that pass's attachment stores, so the pass's whole-tile store no longer overwrites it; this costs at most one fragment-stage wait per compute encoder that follows such a pass. A draw or dispatch whose native compute pipeline is missing fails its command buffer with VK_ERROR_OUT_OF_HOST_MEMORY instead of being skipped, and a compute pipeline whose background build fails no longer marks the device lost: work that binds it fails with VK_ERROR_OUT_OF_HOST_MEMORY and the device keeps running. A Metal pipeline compile that fails writes its error and program name to the log, and one that fails because the Metal compiler service was interrupted or timed out is compiled once more. Polygon-mode, FSR coarse and geometry Mesh pipelines that build on their first draw reach command buffers recorded on other threads only as a complete set. After an application creates a buffer with sparse residency, a geometry shader that writes to a buffer at an index returned by an atomic operation performs that atomic once per invocation, as it does without sparse residency, so the counter no longer doubles and the writes no longer leave unwritten entries.

Non-ASTC compressed 2D sparse images without cube compatibility keep their mip data in canonical pages, so uploading one mip no longer changes another. Images bound to the same memory share page identity. Copies between ordinary and canonical compressed images preserve opaque native mip layouts through a staging buffer used one layer at a time; those copies allocate the buffer and order its reads and writes, with no additional draw waits. Standalone stages retain the canonical 2D route for images bound later, while ordinary descriptors select native sampling. Constant-offset buffer reads use Metal's constant address space, input attachment views preserve nonzero mip and layer bases, and macOS 26 index ranges include the final index. Workaround 14 applies only to constant operands; disabling all workarounds keeps them disabled, and workaround 10 is off on Apple9 and later. Indirect geometry kernels on M1 and M2 use the upstream threadgroup spill workaround. Native float32 filtering follows Metal capability reporting without removing software minimum/maximum sampling. Apple11 adds native read-only RGB8 and RGB16 texel buffers and, with a supporting OS and SDK, floating-point image-view minimum LOD; earlier systems retain shader LOD clamping and RGB32 buffer emulation. Metal GPU captures support debug-label markers and an explicit immediate mode. Captures are declined while timestamp heaps are live, or ended when a heap is allocated, so queries and encoder timing retain real counters. Ordinary device and timestamp-heap lifetimes leave Metal capture control inactive. Native Mesh draws spanning more than 2,097,152 groups store and reload their attachments between slices, so each render encoder holds one physical slice and consecutive large draws no longer exhaust one pass's binning work.

Archive temporary-file cleanup runs once per process on a utility thread instead of starting for every Vulkan device, so applications that create many devices no longer queue repeated directory scans. Native archive pieces are unlinked as soon as Metal opens them, and piece writes create no atomic-write side files; open archives retain their contents for warm-cache lookups and process exit releases their storage. Cleanup recognizes interrupted writes and removes owner-less names only after a day. Available system memory uses the kernel page size on macOS, including translated x86_64 processes, so Rosetta no longer reports one quarter of the available memory. The memory budget uses the same allocation usage returned beside it and removes redundant Metal usage and working-set reads.

Ray-tracing launches in one command buffer reuse one bounded stack and lane-state arena instead of keeping a full-grid arena for every launch until reset. The arena normally uses at most 1/64 of the device working set, or up to 1/8 when a pipeline stack leaves fewer than 1024 lanes in 1/64. Larger grids run as consecutive dispatches over the same arena, ordered behind earlier launches. Ordinary draws and dispatches keep their allocation paths.
