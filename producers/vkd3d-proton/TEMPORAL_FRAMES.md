# Temporal frames

A temporal frame is one DLSS Super Resolution or Ray Reconstruction evaluation, as the Vulkan driver receives it. It carries the game's images and values to MacLauncher's graphics pipeline. The pipeline selects and runs the upscaler, any effects and frame generation. The frame is information only: a driver that receives it forwards it and does not upscale it itself.

## Structure

`VkTemporalFrameInfoMVK` ([vk_temporal_frame.h](vk_temporal_frame.h)), with `sType` 1000999101, is in the `pNext` chain of a `vkCmdPipelineBarrier2`. KosmicKrisp's `kk_temporal_frame_info` (`kk_temporal.h`) has the same layout.

| Field | Meaning |
| --- | --- |
| `featureId` | The temporal history: one per NGX feature, unique within the process. |
| `frameId` | Greater than 0 and new for every evaluation of the feature. |
| `featureType` | 1 for Super Resolution, 2 for Ray Reconstruction, 3 for a late scene. |
| `images`, `formats` | Slots: color, depth, motion, output, exposure, diffuse albedo, specular albedo, normals, roughness, specular hit distance, HUD-less color and UI. Color, depth, motion and output are required. A format other than `VK_FORMAT_UNDEFINED` is the view to read: integer-typed images are read as the float format of their bits. |
| Offsets and extents | Color, depth and motion are read at their offsets over the render extent, or over the output extent when motion is at display resolution. Output is written at its offset over the output extent. An extent of 0 means the image's extent less the offset. |
| `flags` | Auto exposure 0x1, reset 0x2, reversed depth 0x4, display-resolution motion 0x8, jittered motion 0x10, HDR (linear) color 0x20, valid camera 0x40, infinite far plane 0x80, roughness in normal alpha 0x100. |
| Values | Motion vector scale, jitter offset, pre-exposure (0 means none), sharpness and frame time in milliseconds (0 means unknown). |
| Camera | With the valid-camera flag: positive near and far plane distances (far 0 with an infinite far plane) and the vertical field of view in radians. World-to-view and view-to-clip matrices, row-major, of row vectors, accompany Ray Reconstruction and admitted Streamline Super Resolution metadata. |
| `pReleaseFeatureIds` | Features destroyed since the previous frame. |

`VkTemporalFrameMasksInfoMVK`, with `sType` 1000999103, can follow in the frame's `pNext` chain. It carries two optional masks, each with its own format and offset, read over the render extent:

| Field | Meaning |
| --- | --- |
| `reactive`, `reactiveFormat`, `reactiveX`, `reactiveY` | The reactive mask: higher values give the current color more weight than the history. DLSS supplies its bias-current-color mask here. |
| `transparency`, `transparencyFormat`, `transparencyX`, `transparencyY` | The transparency and composition mask: pixels whose color comes from transparent or composited content without matching depth and motion. |

A format of `VK_FORMAT_UNDEFINED` is the image's own. A frame without the structure, or with `VK_NULL_HANDLE` in a slot, has no such mask.

A late scene (`featureType` 3) completes an earlier frame of the same feature: `featureId` and `frameId` are that evaluation's. It carries only the HUD-less color and UI slots, each optional, and the reversed-depth, valid-camera and infinite-far-plane flags with the camera values; every other member is 0 and it releases no features. A game supplies these after its evaluation of the frame: Unreal Engine's Streamline plugin tags its HUD-less color and UI color and alpha, and sets the frame's camera, after its own DLSS pass. The late scene is recorded where the game supplies them, so their contents are those of that frame, and it serves that frame's frame generation.

## Scene attachments

Drivers bind supplied matrices and AOVs with `rsBindTemporalSceneMatrices` and `rsBindTemporalSceneAovs` before processing the same classic command buffer. Both matrix contracts use row-major row vectors, so supplied finite, nonzero arrays are copied unchanged. Zero or nonfinite matrices remain absent. No clip-range flag is inferred.

The fixed guide conventions follow Streamline `b998246a3d499c08765c5681b229c9e6b4513348`, `docs/ProgrammingGuideDLSS_RR.md` sections 4.1.1–4.1.5 and 4.1.9, and `docs/ProgrammingGuideDLSS_G.md`, “Buffer requirements”. Diffuse and specular albedo are linear material reflectance. Roughness is the material roughness scalar in R, or normal alpha when explicitly flagged. Specular hit distance is a world-space distance; consumers requiring view units decline it without a declared conversion. Normal encoding and view/world space remain unknown because the carrier does not declare them.

HUD-less color follows the backbuffer color space and postprocessing. UI RGB is premultiplied by alpha, with zero alpha outside the UI. The carrier does not declare the backbuffer color domain or the matching composition pass, so those fields remain unknown independently of the SR color contract. Resources are retained with this metadata; consumers requiring an unknown convention decline the attachment. No texture or identity matrix substitutes for absent data.

## Producers

- D3D12: VKD3D-Proton's `ID3D12GraphicsCommandListMetalFX` records the frame in the game's command list, followed by a barrier without the structure. `ID3D12GraphicsCommandListMetalFX1` ([vkd3d_metalfx.h](vkd3d_metalfx.h)), which every command list also answers with the same methods followed by two more, adds the late scene: `TemporalFrameId` returns the frame id of a scaler's latest evaluation, and `LateScene` records a late scene for one of the scaler's evaluated frames in the command list that supplies it, with the same following barrier. It declines a missing scaler, frame 0, a frame the scaler has not evaluated, and a scene with no readable image and no camera.
- D3D11: the NGX core records the frame and the same following barrier in a command buffer of its own. It submits that command buffer on DXVK's queue, after the immediate context's flushed commands, through DXVK's interop interfaces (`IDXGIVkInteropDevice`, `IDXGIVkInteropSurface`).

In both APIs the NGX core passes `DLSS.Input.Bias.Current.Color.Mask` and its subrect base as the reactive mask. DLSS reserves its transparency mask, so NGX frames carry none.

MacLauncher's FidelityFX API proxy (the `fidelityfx-api` package) records each FidelityFX upscale dispatch the same ways: on Vulkan, the frame and the following barrier in the dispatch's command buffer, when the device's `driverInfo` names `temporal-sr` and it has `vkCmdPipelineBarrier2`; on D3D12, through `ID3D12GraphicsCommandListMetalFX`. Its frames carry FidelityFX's reactive and transparency-and-composition masks at the origin, and the camera near and far planes and vertical field of view as `CameraValid` values; FidelityFX has no camera matrices. Feature ids of these Vulkan frames carry `0x464658` ("FFX") in their top bytes.

The NGX core takes the camera from the game's own Streamline interposer, which stays the game's NVIDIA-signed file. Streamline passes the camera only in `slSetConstants`; its DLSS plugin gives NGX none. When NVIDIA's NGX library initializes the core in the game's process, the core finds the loaded module that exports Streamline's application API (`slInit`, `slGetNewFrameToken`, `slSetConstants` and `slEvaluateFeature`) and installs in-memory MinHook detours on `slSetConstants` and `slEvaluateFeature` ([ngx_streamline.cpp](ngx_streamline.cpp)). `slSetConstants` copies validated perspective constants for its frame token and viewport ([streamline_camera.hpp](streamline_camera.hpp)); orthographic, oblique and shifted projections, and constants Streamline rejects, give none. `slEvaluateFeature(kFeatureDLSS)` selects the copy of its frame token and viewport as the camera of the evaluations on its thread, as the graphics pipeline's 64-byte `RSTemporalCamera`, and restores the previous camera after the original call, so nested evaluations keep their caller's camera. Both detours return the original result unchanged. The scalar path copies the same 64-byte camera under its existing lock. An evaluation without matching Streamline constants has no scalar camera. The core stays loaded while the detours exist; an interposer loaded again later is detoured again.

A game can also set Streamline constants and evaluate DLSS Super Resolution through NGX itself, outside `slEvaluateFeature`: Unreal Engine's DLSS plugin beside its Streamline plugin, which sets constants only while DLSS Frame Generation runs or with `-slforcetagging`. Neither call names the other's frame. `slSetConstants` therefore also records a camera derived only from the unjittered view-to-clip matrix (`projectionCamera`): near and far from its depth terms, the vertical field of view from its vertical scale, with the declared depth direction. A depth term at exactly the far depth is an infinite far plane, so Unreal Engine's reversed-Z projection gives the engine's near plane and an infinite far plane; the plugin's own near and far plane values, which need not match the projection, are not used. Jitter offsets match when they are equal or negated on both axes, as the two plugins' conventions may differ; the first exact binding fixes the game's convention, since a nonzero offset is never both. A Super Resolution evaluation made with no `slEvaluateFeature` on its thread takes that camera only when exactly one frame and viewport set constants since the previous such evaluation, so they are this frame's or the previous frame's, their jitter offset matches the evaluation's and not the previous evaluation's, and their depth direction is the evaluation's. A temporal upscaler's jitter changes every frame, so that is the same frame. Constants of several frames or viewports, of another frame, without a jitter offset, or before the first evaluation give that evaluation no camera; so does an offset that matches both evaluations. Constants set after their frame's evaluation are never given to the next one. Unreal Engine sets its constants after its DLSS pass, so on that route no evaluation receives a camera. Such constants follow their evaluation exactly when they are the first constants since the latest direct evaluation and their offset matches that evaluation's and not the one before it. Their camera then serves that frame's frame generation, which runs at presentation, after the constants: the core writes it with the evaluation's own jitter offset to `effect-plan.temporal-camera`, a 4096-byte file beside `effect-plan.json` (`ngx_late_camera.h`). MacLauncher creates that file while an enabled frame-generation row consumes the camera and removes it otherwise; the core maps and clears an existing file at its first direct evaluation and never creates or resizes it. The graphics pipeline maps the same file once it exists. After the first record, a frame-generation row that needs a camera admits a scene without one, and its generation stage gives that scene the record whose jitter offset equals the scene's bit for bit, among all four retained records with a unique jitter offset; a frame without such a record is not generated. Temporal upscalers need the camera at the evaluation itself, so on this route they receive none. The depth row's x and y terms of the projection (a jitter or off-centre offset) are allowed, and an undeclared depth direction is the matrix's own. The core logs the first binding, the first occurrence of each reason an evaluation has none, each reason a projection gives no camera with its matrix, the first occurrence of each follow outcome, and after 1000 constants how many followed their evaluation exactly.

## Optional Streamline scene metadata

The existing scalar camera is independent of the additional scene capture. An enabled graph row requiring scene matrices or HUD images activates a stable one-byte mapped demand file beside `effect-plan.json`. The launcher updates that file in place during publication and rollback. The core maps it once at initialization and uses atomic reads, with no per-evaluation file operations or watcher. Off clears optional cached inputs, and transition epochs reject in-flight captures from the earlier demand state. The scalar camera path, signed interposer and original call results remain unchanged.

Additional constants retain the complete supplied unjittered projection and derive world-to-view from the supplied finite, orthonormal camera basis and position. Projection inversion validates the transform without replacing its terms. A shifted or orthographic projection can therefore have full matrices while supplying no scalar perspective camera. The carrier does not gain an inferred clip-range flag.

Optional detours on `slSetTagForFrame` and `slSetTag` observe HUD-less color and UI color-and-alpha tags only after the original call succeeds. Framed tags match the evaluation's exact frame token and viewport and are consumed once. Legacy evaluate-time tags require the exact next evaluation command object; tags inside an evaluation are scoped to that evaluation. Immediate-only lifetimes, unsupported precision transforms, stale or ambiguous tags, subregions and late present-time tags remain absent. An evaluated frame/viewport cannot acquire late tags through another evaluation. Non-DLSS evaluations discard matching one-shot metadata and cannot inherit an outer evaluation's extra scene packet. Nested and exceptional exits restore the caller's state.

Native tag pointers are interpreted only inside the actual typed NGX call on the exact evaluation command object. Full resolved textures must belong to that device. On Direct3D 12, `ScenePacketScope` publishes `NgxScenePacketV1` under its private GUID only around the original temporal call and restores prior data afterwards. The translator consumes it once and validates command identity, the original color/depth/motion/output tuple, regions, jitter and motion scale. Optional HUD/UI resources must additionally be native resources of that translator on the actual device; invalid optional attachments are dropped without rejecting the Super Resolution request. The temporal descriptor and vtable keep their layouts. On Direct3D 11 the admitted data enters the existing DXVK interop record, and attachment references stay retained through the existing submission-slot fence. No new queue, GPU wait or presentation request is added.

These matrices and image slots preserve the API's declared data, not a fabricated HUD composition contract. Missing backbuffer color and matching composition-pass conventions remain unknown and may prevent a provider from using a separated HUD.

## Frame-generation API boundary

The command-list interface retains `SupportsFrameInterpolation` and `FrameInterpolate` for ABI compatibility. They return `FALSE` and `E_NOTIMPL`. The NGX core therefore reports DLSS-G unavailable. Its Streamline detours attach admitted constants and tags to the exact real Super Resolution evaluation; they do not create a present-time DLSS-G scene producer.

The carrier's HUD-less and UI slots and camera matrices are scene attachments. Driver bindings retain supplied HUD/UI textures, but their color domain and matching composition pass remain unknown unless a producer declares them. Slot presence alone does not establish the inputs required for HUD-separated interpolation.

A frame-generation producer must identify a real frame and establish one presentation owner. Streamline's DLSS-G plugin uses a proxy swapchain to schedule the NGX interpolated output followed by its real output. Returning a generated image through that contract while also scheduling shared generation would create two presentation owners. The existing Super Resolution carrier does not establish an input-only DLSS-G contract.

D3DMetal's native MetalFX interpolation follows a separate caller-owned contract in the shared graphics processor. One enabled 2× generation row can write the exact output requested by the SDK call, while the game retains presentation. The classic Metal observer follows complete copies and registered format views to current drawables on the actual device and queue. Immutable image versions, enqueue order and acquisition identity establish both presentation endpoints; unobserved writes, partial copies, other queues and reused acquisitions retain the original SDK output. The consumed interval follows these exact images into the shared presenter and suppresses another generation pass. Off adds no input capture or provider load. This native SDK route also serves native MetalFX applications and does not change this NGX interface or its capability advertisement.

## Driver

- **Forwarding.** The driver forwards the frame with `rsProcessTemporalFrame` (graphics `frame.h`). It does this in command order: after every earlier command on the queue has completed, and before any later command starts. The method is `rsGetTemporalMethod`, or MetalFX when none is selected. The driver creates and encodes no MetalFX scaler, interpolator or other upscaler of its own.
- **Masks.** The graphics pipeline reads `RSTemporalFrame.reactive` and `.transparency` at the color offset over the render extent. A driver passes a mask when its offset equals the color offset and its image covers that region; it leaves a mask at any other offset absent.
- **Command buffer.** The frame goes to a classic `MTLCommandBuffer` (`commandBufferKind` 0) with retained references, before it is committed. Ordered effects and frame generation run only on such a command buffer.
- **Tracked output.** The pipeline writes a tracked texture that the driver keeps for each feature. It has the output extent, private storage and shader-read, shader-write and render-target usage. It is passed with output offsets of 0 and its full extent. After the call, the driver copies it into the frame's output image at the frame's output offset. Frame resources carry no fence, and ordered effects need the complete output texture. The driver copies only while the tracked texture holds a frame: from the first call that encodes one after the texture is allocated, or reallocated for a new output extent or format. Until then, the frame's output image is left untouched. Later, a busy call leaves the previous image in the tracked texture, so the copy always writes a complete image. MacLauncher KosmicKrisp also keeps and copies the previous image after a failed call, while MacLauncher's MoltenVK build reports a failed call as a command buffer error.
- **Owners.** Each `featureId` has one pipeline owner on the device. A released feature ends with `rsReleaseTemporalOwner`, after its last frame has completed.
- **Availability.** `driverInfo` names `temporal-sr` only under two conditions: `rsProcessTemporalFrame`, `rsGetTemporalMethod` and `rsReleaseTemporalOwner` resolve in the process, and MetalFX's temporal scaler supports the device. It names `temporal-rr` only when Ray Reconstruction frames are forwarded. The NGX core offers each DLSS feature only where the device names its word. DLSS Frame Generation is not offered: MacLauncher's frame generation runs from the forwarded Super Resolution frames.
- **No cost without the pipeline.** The symbols are resolved once per process. Without them, the driver names no word and gives frames no handling. A barrier without the structure takes no new path.
- **Synchronous Metal.** Metal objects are created synchronously, without completion handlers.

## NGX signing

The package signs its actual NGX core with SHA-256 Authenticode after stripping. Each build creates a self-issued MacLauncher NGX code-signing certificate and deletes the private key after signing. The public certificate and the x64 `ngx-trust.exe` helper are declared by `manifest.json` as `ngxTrust`. During Play, MacLauncher installs that public certificate in the selected Wine prefix’s Root store and verifies the core with `WinVerifyTrust`, with UI and network retrieval disabled. A failed verification removes a newly added certificate. The helper does not change macOS trust or redirect signature checks to another file. Packages and their signed inventories identify the resulting core and public certificate; the signing key and certificate creation times vary between builds.

The certificate carries the project URI in its subject alternative name. A per-prefix mutex serializes trust changes. The helper retains one project-owned root and records its thumbprint in the fixed `HKLM\Software\MacLauncher\NGX` value `CertificateThumbprint`. Selecting another signed package removes the previous owned root before importing its replacement; the next thumbprint is recorded before the add, so an interrupted import can be reclaimed. Reusing a package verifies the existing root without importing another certificate. Other roots are preserved.

Late HUD tags are copied in the tagging command list before the tag call returns. This accepts `eOnlyValidNow` images only for that inline copy; delayed evaluation capture continues to require `eValidUntilEvaluate` or `eValidUntilPresent`. The late scene uses the evaluated scaler frame ID and the exactly followed camera. Framed tags must match the constants’ frame token and viewport; unframed tags must match the followed evaluation and viewport. A scaler that has advanced past that frame is rejected.

Immediate D3D12 scene intake also accepts the `Resource` layout used by producers that zero its metadata prefix and fill its declared texture fields. This is the same field layout consumed by Streamline 2.2.1; no alternate layout is inferred. A null native texture, nonzero unknown structure identity or version, incompatible image type, foreign device, or wrapped resource that the translator cannot consume is rejected.
