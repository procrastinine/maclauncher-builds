# Darwin FEXCore overlay

The patches apply in numeric order to the FEX source selected by the producer's gitlink. The core patch accepts Darwin as an embedding target and builds `Source/Common`; the embedding host supplies its executable target.

`0001-darwin-core.patch` adapts the platform boundary, executable allocation, per-thread JIT writes and the register allocator's reserved x18. `0002-darwin-code-guards.patch` sizes guards to the host page and replaces the final owned MAP_JIT page with an ordinary inaccessible mapping. Temporary emission buffers remain ordinary writable mappings with a host-page guard.

`0003-darwin-signals-and-guest-state.patch` provides header-only embedding interfaces:

- `FEXCore/Darwin/SignalDelegator.h`: process signal installation, unaligned atomic backpatching, guest code-write faults and guest exception delivery from Darwin arm64 contexts.
- `FEXCore/Darwin/GuestState.h`: a scoped current guest thread and a template that fills the embedding library's CPU accessor table from FEX state.

The embedding host installs the delegator before starting guest threads, and joins those threads before uninstalling it. Each OS thread binds its guest with `FEXCore::Darwin::ThreadScope` while executing translated code and native guest-library calls. Mapping callbacks supply stable guest permissions and distinguish code-write traps from read-only guest mappings. Invalidation covers all guest threads and shared aliases before the delegator restores write access. Exception callbacks select a guest continuation by editing the spilled guest state. An unmasked floating-point exception in a native guest-library call uses the host's non-returning floating-point exception continuation.

Only owned complete host pages may be unprotected. Native faults and guest mappings that do not satisfy the code-write contract pass to the previous signal handler with its reported mask and restart flags. A previous one-shot disposition can only be preserved when Darwin reports it. The host supplies an alternate signal stack for each guest thread. The Darwin host does not enable SVE or fault-free synchronous dispatch without the corresponding host context support.

The CPU accessors reflect the selected FEXCore representation. The MXCSR write mask is the mask emitted by its FXSAVE implementation. The x87 environment carries FEX's control word, status, physical register tags and instruction pointer; data pointers, selectors and FOP require additional core state. Full 80-bit x87 arithmetic and software x86 memory ordering remain enabled.

`0004-darwin-context-state.patch` supplies `FEXCore/Darwin/ContextState.h`. `InstallContextAccessors<Frame>(table)` binds the embedding library's Capture/Restore table to the current guest thread. Capture records the raw guest entry state in its named registers and FXSAVE64 image; the guest library owns adjustments to saved call continuations. Restore retains current CS/SS, merges the user-changeable RFLAGS bits, restores register and floating-point state and resets FEX's return prediction stack. Upper YMM halves retain their current values during legacy FX restore. The host's control-transfer mechanism resumes execution without applying an ordinary native-call result or RET. FOP and FDP remain unavailable in the selected core representation.

`0005-darwin-single-step-writes.patch` opens the same scoped JIT write mode for single-instruction compilation as ordinary block compilation. This covers the code publication used when resuming a self-modifying instruction or the guest trap flag.

`0006-x87-status.patch` preserves the x87 exception-status bits across environment restoration, status reads, FNCLEX and FNINIT. `0007-precise-memory-pop.patch` commits RSP after a memory POP store succeeds, while retaining the post-incremented address calculation for RSP-relative destinations. `0008-darwin-interrupt-page.patch` sizes and aligns the thread's interrupt fault page to the 16 KiB Darwin host page, so protecting it covers no other thread state. The embedding host protects that page to take an asynchronous guest exception at FEXCore's next interrupt check, where its per-block register cache has written every guest register back. FEXCore emits the check only when its GdbServer option is set, and the host sets that option for the check alone: in FEXCore the option's only use is enabling this check (`NeedsPendingInterruptFaultCheck`), and no debugger server is part of the host. `0009-taken-backward-branch-interrupt-check.patch` runs that check on a taken backward conditional branch as on an unconditional one, so a loop whose back edge is conditional reaches a check on every iteration; the check sits after the inverted condition, so an interrupt there resumes at the branching instruction, which branches again.

The overlay is MIT-licensed. The core platform patch derives from the existing Darwin adaptation in this producer. Signal state reconstruction follows FEX's MIT Linux frontend, `Source/Tools/LinuxEmulation/LinuxSyscalls/SignalDelegator.cpp` and `SyscallsSMCTracking.cpp`. Existing FEX copyright and license notices remain in the selected source. The Darwin context and mapping code is an independent implementation and has no Wine dependency.

The x87 status change is by Avery Felts from the MetalSharp-Wine FEX series. The memory POP change is by Alexander Theißen from the Mach9 FEX fork. Both retain their original authorship, MIT license, source commit and origin in the patch metadata; the x87 adaptation includes only the generic FEXCore changes.

`0010-x87-control-read.patch` masks reserved x87 control-word bits on guest stores and Darwin state reads while retaining the word as loaded. It adapts Alexander Theißen's MIT change `fa4f65e2546931869554029cdf1472b49afb6863` from [athei/FEX](https://github.com/athei/FEX/commit/fa4f65e2546931869554029cdf1472b49afb6863).

`0011-x87-quiet-compare.patch` distinguishes quiet x87 compares from signaling compares, including unsupported 80-bit encodings. It adapts Gauthier Piarrette's MIT change `c1a1f007c0a749737af70c755a3681589c75b045` from [Highball engine](https://github.com/gauthierpiarrette/highball-engine/blob/161d7a8495d041d2901d07ff3b4fffeed9be1a4b/fex/patches/0008-x87-FUCOM-and-FUCOMI-raise-invalid-only-for-a-signal.patch).

`0012-smc-direction.patch` writes a changed direction flag back at each guest instruction boundary while retaining it in the register cache. It adapts the MIT change `a6254f3e21648e433c34c9fef60c72afc20ac6e8` from [the original source](https://github.com/athei/FEX/commit/a6254f3e21648e433c34c9fef60c72afc20ac6e8). Original authorship remains in the patch.

`0013-smc-vector-cache.patch` writes cached MMX and upper YMM values back at instruction boundaries in writable executable ranges so inline code-write faults retain them. It adapts the MIT change `6668c5d85af88b79b7c6a4b8950525367e034609` from [the original source](https://github.com/athei/FEX/commit/6668c5d85af88b79b7c6a4b8950525367e034609). Original authorship remains in the patch.

`0014-exact-x87-remainders.patch` computes full 80-bit FPREM and FPREM1 reductions in integers, reporting partial reduction, quotient bits and denormal operands. It adapts the MIT change `943ed32e5f0406407f8e04306a50b7c06e5fc180` from [the original source](https://github.com/gauthierpiarrette/highball-engine/blob/161d7a8495d041d2901d07ff3b4fffeed9be1a4b/fex/patches/0010-x87-exact-FPREM-and-FPREM1-with-quotient-bits-and-pa.patch). Original authorship remains in the patch.

`0015-x87-rounding-controls.patch` keeps FTZ and DAZ controlled by MXCSR and applies restored x87 rounding in the optional reduced-precision implementation. Full 80-bit x87 remains the default. It adapts the MIT change `0433ca10ac903963c34a2893241abc8ac0214f2a` from [the original source](https://github.com/athei/FEX/commit/0433ca10ac903963c34a2893241abc8ac0214f2a). Original authorship remains in the patch.

`0016-x86-undefined-flags.patch` clears auxiliary flags for logical and shift operations, preserves selected parity and multiplication flags, and adjusts variable-shift overflow. Immediate multi-bit shifts retain their existing overflow behavior. It adapts the MIT change `14062147078cfd44010a07078e95fde552065696` from [the original source](https://github.com/metalsharp/MetalSharp-Wine/blob/a7018b6992a99dfc04b73e1f8960c6ec3d77ea6d/patches/fex/0031-FEXCore-Match-x86-results-for-flags-left-undefined-b.patch). Original authorship remains in the patch.

`0017-signed-memory-loads.patch` uses one signed native load for MOVSX and MOVSXD memory operands when ordering permits it, retaining the software TSO load path. It is paired with 0018 for access-size displacement handling. It adapts the MIT change `8c94f35ce9ee0f13a8ab5115bfa68a2fe80500ca` from [the original source](https://github.com/metalsharp/MetalSharp-Wine/blob/a7018b6992a99dfc04b73e1f8960c6ec3d77ea6d/patches/fex/0015-FEXCore-Sign-extending-loads-for-MOVSX-MOVSXD-from-m.patch). Original authorship remains in the patch.

`0018-signed-load-offsets.patch` uses the memory access size for signed-load offset inlining while retaining the destination width. It completes the required 0017/0018 pair. It adapts the MIT change `2cb3f42ccf6730e010e660136f9e8086a5114542` from [the original source](https://github.com/metalsharp/MetalSharp-Wine/blob/a7018b6992a99dfc04b73e1f8960c6ec3d77ea6d/patches/fex/0019-FEXCore-Inline-LoadMemSExt-offsets-against-the-acces.patch). Original authorship remains in the patch.


`0019-darwin-zero-anonymous-caches.patch` clears anonymous lookup caches, cached native return addresses and allocator bitsets on Darwin. Aligned host pages use `MADV_ZERO`; partial host-page edges use exact stores to preserve adjacent entries. Darwin `MADV_DONTNEED` is an access hint and does not clear resident bytes. Native code-file page eviction is outside the Darwin path.
